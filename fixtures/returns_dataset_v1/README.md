# Fixture set: `returns_dataset_v1`

**What this is:** 6 synthetic test units (11 images total) for exercising the Returns Manager
pipeline end-to-end — identity, completeness, condition, disposition, and the `uncertain`
path — before real fixture photography exists.

**What this is not, and must never be used as:**

- **Not real product photography.** Every image is a flat-icon diagram generated by
  `generate_fixtures.py` (Pillow), not a photo of a physical item.
- **Not eval data.** Per `CLAUDE.md`, `fixtures/` is dev-only; the Round 2 eval set required
  by `RULES.md` is ≥50 unseen units independently labelled by two humans. Nothing here
  counts toward that, and no evaluation report may cite results from this set as accuracy
  numbers.
- **Not a repeat of F-008.** The images generated here decode fully, are byte-distinct across
  scenarios (verified: `sha256sum images/*.jpg | sort | uniq -d -w64` is empty), and every
  image is visibly watermarked `SYNTHETIC TEST FIXTURE — NOT REAL PRODUCT EVIDENCE` plus a
  unit/SKU/state header, so it cannot be mistaken for genuine evidence at any point downstream
  (storage, model input, UI, or eval).

## Why synthetic, and why now

This session has no general internet access (outbound egress is allowlisted and blocked
scraping any product-photo source, confirmed against Wikimedia Commons too) and no
image-generation model available, so sourcing or fabricating photographs of real returned
items was not possible. Rendering clearly-labelled synthetic diagrams — rather than silently
skipping the request or reusing another F-008-style unlabeled placeholder — keeps to the
project's own honesty rule (§6.1: "say what you built") while still giving you something
concrete to run the pipeline against today.

**Before you build the real eval set:** replace this directory's role with actual phone
photos of physical items per `RULES.md` §5 (≥50 unseen units, two independent human labels).

## The 6 test units

| unit_id | SKU | scenario | exercises |
|---|---|---|---|
| `TEST-UNIT-001` | LAMP-LED | complete, unused, no damage | clean restock path |
| `TEST-UNIT-002` | LAMP-LED | USB cable absent | completeness FAIL (essential + replaceable) |
| `TEST-UNIT-003` | PUZZLE-500 | box reopened, ~27 of 500 pieces visible | completeness FAIL (essential + non-replaceable) |
| `TEST-UNIT-004` | BOTTLE-750 | visible dent + crack on the body | condition FAIL / damage |
| `TEST-UNIT-005` | CABLE-USBC | box labelled as the cable; contents show a different product | identity mismatch — box-swap defense (F-013 / C06) |
| `TEST-UNIT-006` | BOTTLE-750 | single photo: dark, blurred, cropped at both edges | forced `UNCERTAIN`, not a guessed PASS/FAIL |

Each row in `manifest.csv` / `manifest.json` gives the *expected* check outcomes as a human
reviewer would call them from the image alone — use these as your labels when scoring the
pipeline's actual output, the same way `data/returns_sample.csv` documents columns for the
organiser's synthetic sample data.

`expected_amazon_condition` is left blank everywhere, deliberately: per `CLAUDE.md`
("look rules up"), the condition grade must come from the pipeline grading against the
hashed Amazon rubric snapshot (see ADR-006), never from a hand-typed expectation here.

## How to use it

1. Point your ingestion path (API, CLI fixture loader, or however `returns-manager` intake
   currently works) at one `before_image` + its `after_images` per row.
2. Run the inspection.
3. Compare the produced evidence record's `checks[]` verdicts against the manifest's
   `expected_*` columns — identity, completeness (`parts_missing`), condition, and the
   resulting `outcome.decision`.
3. For `TEST-UNIT-005` and `TEST-UNIT-006` specifically: if the pipeline returns a confident
   `PASS`/`restock`-style result instead of a mismatch or `UNCERTAIN`, that is a bug in the
   check, not a quirk of the fixture — those two units exist to catch exactly that failure
   mode.

## Regenerating

```sh
pip install pillow   # not an agent runtime dependency; only this generator script needs it
cd fixtures/returns_dataset_v1
python3 generate_fixtures.py
```

Deterministic except for antialiasing/JPEG encoder noise; the scenario content, captions,
and watermark placement are fixed by the script.
